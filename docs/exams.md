# 模拟赛管理

插件版本为 0.3.0。入口为「学生管理 → 模拟赛管理」或 `/sms#exams`。

## 初始化

首次由插件管理员打开初始化向导，预览有权查看的过往 Hydro 比赛，逐场选择 Rated。可点击「选择原有 Rated / 已结算比赛」作为选择起点；系统不会替管理员提交。确认区明确统计取消了多少场已有评分，以及历史重算影响。所有旧的绝对分数导入检查点保留，未选中的比赛不自动设为 Rated。确认后初始化入口关闭，后续通过各比赛的设置与核验维护。

## 日常管理

1. 在 Hydro 原有比赛功能中创建比赛及题目，再通过「关联比赛」选择已有比赛，指定参赛班级与类型、难度、Rated、范围、来源和说明。修改元数据需要对应全部参赛班级的 `exams.update` 权限，新增还需要 `exams.create`。
2. 时间、赛制、时长、题目满分来自原生比赛，避免两处编辑产生矛盾。列表中的详情和名称链接直接进入原生比赛页；插件在原生页面上增加模拟赛信息和授权操作区，不替代题目、公告、原生赛制和成绩表。
3. 已关联比赛及其成绩表、题目、提交等子页面同时检查原有 Hydro 权限与 SMS `exams.read` 的班级范围。原生隐藏比赛及分组限制继续生效。多班级比赛的查看与导出采用关联班级交集，写入及整场代码包提交要求覆盖全部关联班级；班级详情及课程关联复用该范围。
4. 支持按班级、名称、类型和归档状态查询。导出在本页操作区提供 Excel / CSV，单独检查 `exams.export`。归档不删除原生比赛、提交、成绩或已发布 Rating。

## OI 代码包

需要同时安装独立的 `hydro-offline-judge` 插件。安装时需要同时在 Hydro 注册这两个插件。OI 比赛详情页在授权且插件可用时显示「提交离线代码包」，在当前比赛页弹窗内完成上传、预览、确认、评测进度与原批次续办；没有独立功能页。列表中的代码包链接也定位到对应比赛页。两个插件均需使用 0.3.0。

- 操作者必须为关联班级的实际任课教师（所有关联班级均在其任教范围），同时拥有对应 `exams.submit` 模块权限，或为 SMS 插件管理员。普通成员、班外教师以及仅有 Hydro 管理权限但没有 SMS 授权的账号不能导入已关联比赛。
- 仅接受结束后的 OI 专用离线比赛；需正常本地代码评测题，比赛不能混入其他正式提交，不支持个人计时、团队或分组限定，封榜需先解除。原生比赛与语言限制不被放宽。
- ZIP、`submissions.csv`、UID、题号、源代码路径和服务器语言 ID 的格式、大小限制、预览及唯一正式批次规则由离线评测插件维护。代码包中所有 UID 还会检查是否属于关联班级。
- 比赛只允许确认一次正式代码包；包含的选手登记为参赛，预览不修改参赛状态，确认、续办、执行均重新鉴权。

## 赛后订正与核验

赛后已关联班级成员可继续通过原生提交表单提交正常源代码，提交被标注为 `smsCorrection` 并从原生记录参数中移除正式比赛关联，因此只进入普通评测记录，不更新正式比赛 journal、排名或 Rating。需要保留原生登录、题目访问、语言、文件大小、限流与同源保护。若正式离线批次尚未完成，订正暂时拒绝。

设置 Rated 不会直接结算。管理员在比赛结束、正式评测全部完成后，通过「核验」预览官方名次与分数，确认后发布 Rating。配置、正式成绩或 Rating 版本变化会使旧预览失效。已核验评分不会因订正或自动定时任务改变。修改难度、重测正式记录或取消 Rated 后，需要管理员重新核验；旧评分在新核验通过前保留。算法仍在独立 Rating 模块中。

管理操作与导出均记录审计日志；测试文件、代码包与测试回调驱动不随插件提交。

## 筛选与结算预览

模拟赛列表支持 Rated／Unrated、待核验／已结算／未结算，以及按比赛开始日期筛选。日期按北京时间计算，起止日期均包含当天。待核验包含新设为 Rated 尚未发布、正式成绩或配置改变，以及取消 Rated 尚未核验撤销的比赛；已结算筛选仅显示当前无需重新核验的已发布比赛。列表、分页总数和导出共用筛选条件，班级访问权限不变。

管理员核验时可预览选手姓名、用户名、UID、正式成绩、名次、得分率、赛前／赛后 Rating、涨跌和称号变化。预览与正式发布共用历史重放逻辑，按比赛结束时间恢复赛前状态；不会用当前 Rating 直接估算过去的比赛。取消 Rated 时展示当前 Rating 与撤销贡献、重放剩余历史后的 Rating。预览不发布分数，仍需明确确认；成绩、配置、算法或 Rating 版本变化后必须重新预览。
