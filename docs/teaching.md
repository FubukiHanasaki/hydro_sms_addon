# 课程、排课与班级详情

## 与旧系统一致的业务概念

- **排课计划**对应旧系统 `course_schedule` / `course_schedule_slot`：安排未来每周何时、由谁、在哪个地点上课。一个计划有自己的名称，可包含多个每周时段，支持进行中、草稿、暂停及单次调课、停课、恢复和补课。
- **计划课次**对应旧系统 `core/lessons.py` 的日期实例：由排课计划按查询日期推导。打开课表不会生成实际课程或考勤，也不会向数据库写入课次。
- **实际课程**对应旧系统 `class_course`：一节已经登记的实际授课记录，保存实际日期、开始/结束时间、教师、地点、课程内容、备注、关联模拟赛和考勤。可以独立新增，不需要先建排课；也可以从计划课次登记。
- **考勤**属于实际课程。已有实际课程可经过预览、确认后关联计划课次，保留原考勤；一个计划课次最多关联一个实际课程，一节实际课程最多关联一个计划课次。

不使用「先建立课程目录，再从目录生成排课」的原型流程。参考实现包括旧系统 `handlers/course_schedule_management.py`、`handlers/course_attendance_management.py`、`handlers/lesson_management.py` 和 `core/lessons.py`。

## 入口

- `/sms#courses` 或侧栏「课程管理」：选择班级，查看日期范围内的实际授课记录，独立登记、编辑课程及考勤。
- `/sms#schedules` 或侧栏「排课管理」：按教师筛选跨班级周课表（默认全部教师），查看周课表、切换周次、新建时选择所属班级，编辑排课计划；点击课表中的一次排课可登记实际课程、关联已有课程或调整计划。
- `/sms#organization` →「详情」：班级概览、实际课程、排课、考勤、模拟赛和 Rating 分析。标题、常用操作和标签栏固定，内容独立滚动；手机端采用单列概览与课程卡片。

## 排课

排课管理顶部支持 [批量排课](schedule-batch.md)：Excel/CSV 文件或粘贴 CSV，字段预览、既有与本批时间冲突检查，确认后统一发布。

周视图固定展示 08:00–22:00，卡片按开始时间定位，高度与上课时长成正比（每分钟 1 像素）。同时段课程并排展示；跨边界课程裁剪显示，完全位于时间轴以外的课程单独列出，不删除原记录。时间列与星期标题在课表内滚动时固定，手机端可横向查看。新建排课位于顶部筛选栏右侧，周标题、日期和切周按钮合并为一行。

- 插件管理员管理排课计划；计划教师必须已经加入班级，且具有插件任课教师身份。教师和学生可查看授权范围内的课表。
- 每个计划填写名称、教师、地点、状态、颜色、起止日期、备注及 1–14 个每周时段。每周时段有稳定 ID；不同星期可以设置不同的上课时间。
- 保存分为预览和确认，确认时再次检查班级、教师及非空同名教室的时间冲突，跨班级也检查教师及教室；相邻时间段不算冲突。草稿、暂停和单次停课不占用资源。
- 当前每段计划日期范围最多 731 天。所有日期与时刻按北京时间本地日历解释，不跨日。
- 编辑时指定「修改生效日期」，新版本从该日期起生效，之前的计划版本保留。已经登记的实际课程保留当时的计划快照，修改未来排课不会改写其授课内容或考勤。
- 单次调课保留原课次 ID，调整到另一个星期后仍可在新日期查询到；调课和恢复会重新检查冲突。已有实际课程的计划课次不能直接调课或停课。
- 停课后可「安排补课」，建立带原课次引用的独立排课。
- 班级归档后不能保存新的排课计划。原有计划及实际课程保留。

不恢复旧系统的在班起止时间、时段覆盖及时间纠错验证。名册直接使用当前子域成员，并保留实际课程已有考勤的历史学生。

## 实际课程与考勤

- 插件管理员和该班当前任课教师可以独立登记、编辑实际课程。学生只查看本人考勤、备注和个人统计，不能编辑或读取其他学生行。
- 登记实际课程时可调整实际授课时间、教师和地点；计划时间与实际授课时间分别保存。可以关联当前班级的 Hydro 模拟赛。
- 考勤支持未填写、到课、迟到、请假、旷课。未填写不自动记为旷课，也不计入到课率分母。
- 到课率 =（到课 + 迟到）/（到课 + 迟到 + 请假 + 旷课）。无有效考勤时显示「—」。
- 实际课程内容与考勤单文档原子保存，使用版本校验防止覆盖。请求标识保证新增重试不产生重复课程，复用标识提交不同内容会被拒绝。
- 考勤名单包含当前班级绑定学生及本次实际课程已有考勤的历史成员。服务端拒绝重复 UID、其他班级学生和遗漏已有考勤；退班不会删除历史记录。
- 「关联已有课程」先展示待关联记录及考勤条数，确认后只建立关联，不重建或覆盖考勤；两边均校验版本和唯一关联。

## 班级概览与 Rating

- 概览展示实际课程数、计划课次数、模拟赛、到课率和平均 Rating；可点击指标进入对应标签。
- 组合展示 Rating 走势、考勤环图、近期排课及班级资料。日期范围默认北京时间当月，最多查询 93 天；课程统计按实际授课日期，课表按计划日期，两者独立。
- 模拟赛标签向管理员与班级教师展示当前子域中的 Hydro OI、IOI、严格 IOI 和 ACM 比赛，并显示结算状态。
- Rating 分析包括当前学生分数及称号、区间净变化、平均分走势，以及逐场已结算模拟赛的平均涨跌、中位数、最高及最低涨跌。全站比赛中本班成员的计分结果也参与分析。
- 平均分走势使用导入检查点和真实比赛历史，区间开始前的最后分数作为基线。按当前成员口径统计，学生看到个人口径。
- 导入 Rating 不会生成模拟赛、实际课程或考勤；部署也不会向运行站点写入演示教学记录。

## 接口与存储

全部接口复用 Hydro 会话及插件同源校验：

- `GET /sms/api/teaching/schedules?teacherUid=&from=&to=`：授权范围内按教师汇总的跨班级课表、计划与教师筛选项。
- `GET /sms/api/teaching/classes`：可访问班级和教学权限。
- `GET /sms/api/classes/:id/teaching?from=YYYY-MM-DD&to=YYYY-MM-DD`：班级详情、计划、课次、实际课程、考勤和 Rating 分析。
- `POST /sms/api/classes/:id/schedules`：保存独立排课计划，先 `preview: true` 再带 `previewToken` 确认；编辑须提供 `id`、`version`。
- `POST /sms/api/classes/:id/courses`：登记或编辑实际课程，须提供请求标识；从排课登记时另带 `lessonId`、`lessonVersion`。
- `POST /sms/api/classes/:id/lessons/:lessonId`：`adjust`、`cancel`、`restore` 或 `linkPreview` / `link`，须提供当前课次版本。

数据集合：

- `sms_teaching_plans`：独立排课计划及按生效日期保存的版本。
- `sms_teaching_adjustments`：临时调整和稳定课次引用。
- `sms_teaching_records`：实际授课、可选计划快照、模拟赛引用、参与者考勤及版本。

写入通过实例级短期锁串行处理，实际课程及其考勤使用单文档原子更新，关联有唯一索引。与宿主成员管理之间没有跨集合强事务。审计记录字段名称、操作和结果，不保存完整教学内容及考勤备注。

第一版原型的 `sms_courses` / `sms_schedules` 保留原始数据；其排课及已完成课次会幂等转换，已录入内容和考勤保留。原型课程目录本身不会被当作一次真实授课。
