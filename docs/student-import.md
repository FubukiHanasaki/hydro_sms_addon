# 学生基本资料批量导入

入口：「学生档案」右上角「批量导入」。插件管理员或获得全局学生导入、新增、读取、修改及绑定权限的账号可读取文件、预览、确认和查看导入记录，使用现有 Hydro 会话和同源校验。基本资料导入不需要敏感资料权限。版本保持 0.2.0。

## 文件与字段

支持 Excel `.xlsx`、`.xls` 和 UTF-8（含 BOM）/ GB18030 CSV，支持 CSV 引号、逗号和换行。每次最多 1000 行资料、50 列、2 MB。第一行必须为字段名；多工作表文件可选择工作表，自动识别常用中英文列名，也可手动调整对应列。姓名必须映射，同一列不能用于两个字段。

| 字段 | 说明 |
| --- | --- |
| 姓名 | 必填，生成姓名全拼账号 |
| 性别 | 男、女、未填写或空 |
| 年级 | 文本，与学生档案字段一致 |
| 学校 | 文本 |
| 学生状态 | 在校、休学、离校；缺省或空时为在校 |
| 入学日期 | Excel 日期单元格，或 YYYY-MM-DD / YYYY/M/D |
| 学习阶段 | 文本 |
| Hydro UID | 绑定已有账号时必填；创建新账号时留空 |
| Rating | 选填，0–100000 的分数，0 分有效 |
| Rating结算时间 | 与 Rating 成对填写；北京时间或带时区的日期时间 |
| 账号处理 | 绑定已有账号、创建新账号、跳过 |

只导入基本资料。生日、电话、家长信息、微信、地址、内部备注、已移除字段、班级身份不在本次导入范围内。Rating 可以作为可选的绝对分数检查点一并导入。界面列出不导入的列；原始文件不写入插件数据库或文件目录。公式和错误单元格要求改为值后再导入，不计算或执行公式。可下载 CSV 空模板，使用 Excel 填写。

## 账号处理与最后结算 Rating

表格映射了「账号处理」时，每行须明确选择「绑定已有账号」「创建新账号」或「跳过」。绑定模式不接受空 UID，创建模式不接受已有 UID，跳过行不会创建账号、档案或 Rating。未提供该列的旧格式仍保持原有自动建号规则。隐藏或筛选 Excel 行不会使其跳过，应显式填写「跳过」。

Rating 和 Rating结算时间必须同时填写或同时留空，空值不等于 0 分。Excel 日期时间保留时、分、秒，纯日期按北京时间零点解释，未来或无效时间拒绝。记录以绝对分数检查点导入，不虚构计分比赛次数。只需要最后结算时，每名学生保留一行最后分数和时间，不必迁移更早的历史。

含选中 Rating 的批次额外要求 `rating.import` 权限。预览显示分数、北京时间和重复状态，不修改档案或 Rating；确认前检查 Rating revision 是否变化。已绑定同一学生且文件非空基本字段一致时可仅追加 Rating，保留原基本资料、敏感资料和备注；资料冲突不覆盖。同 UID、同时间、同分数去重，不同分数阻断。

确认后先准备档案与绑定，再按每批最多 500 条调用 Rating 导入流程。资料完成但 Rating 失败时显示「Rating 待处理」，批次保留为 `rating-pending`，可从导入记录继续，且不会锁住其他学生资料操作。重试会重新核对绑定并预览剩余检查点，已经发布但尚未记入批次回执的记录通过同分同时间去重恢复；不重建账号。逐行完成状态与 Rating 完成数分别显示，未完成的 Rating 不会被标记为全部完成。

## 预览与重复识别

读取文件后先确认列对应，再生成预览。预览按行显示资料、行号、计划用户名、识别原因和当前选择。

- **新增**：没有同名档案，默认选中，确认后建立档案及普通 Hydro 账号。
- **绑定已有档案**：姓名及文件中非空基本字段唯一匹配已有未绑定档案，默认选中。只为其创建/绑定账号，保留原基本资料、敏感资料及备注。
- **跳过**：表格明确选择「跳过」，该行不参与导入。
- **重复**：文件内相同内容、重复 UID、重复匹配同一已有档案，或已有相同且已绑定的档案。自动跳过，不覆盖原资料。
- **疑似重复**：同名但资料不同、同名匹配不唯一，或文件内有同名不同资料。默认不选中；核对名单后勾选，表示明确按另一名新学生创建，不合并或覆盖旧档案。
- **错误**：必填、状态、日期、UID、公式等校验失败，不能选中；修正文件后重新读取。其他有效行可以继续导入。

可取消任何待导入行。列对应和选择发生变化后重新生成预览，用户名也重新分配。预览有效期 15 分钟；确认前重新检查学生资料快照和账号是否仍可用，发生变化则重新预览。

## 账号与结果

新账号通过 Hydro `UserModel.create` 建立，只使用普通默认权限。用户名采用姓名全拼，重名追加数字，初始密码与用户名一致。若文件指定已有 UID，不修改其用户名、密码或权限；不能通过导入绑定内置账号、插件管理员及带额外 Hydro 权限的受保护账号，一个 UID 最多关联一份学生档案。

确认后展示逐行结果。已完成批次可导出本批账号 CSV：仅新建账号填写初始密码，已有账号的密码列留空；初始密码不代表之后修改过的当前密码。插件不保存明文密码，CSV 对可能触发公式的文本作转义。

「批量导入 → 导入记录 → 详情」可查看历史和继续未完成的导入。重复确认同一批次不会重复创建档案或账号；再次上传已导入资料也会进行现有档案重复检查。

## 中断恢复与存储

当前 MongoDB 没有跨集合事务。导入按行处理，失败可能留下部分成功结果和未完成批次。每行使用稳定账号请求标识、固定内部邮箱和档案 ID：Hydro 账号已创建但档案尚未保存时，续办找回同一个账号；档案保存后结果尚未落盘时，续办核对同一档案，不重复创建。

未完成的导入会阻止其他学生资料写入及新的学生批量操作，避免续办覆盖后续修改。任意插件管理员可从导入记录续办；预览只有创建者可确认。外部直接改库或账号抢占造成的冲突需维护人员核对，不擅自覆盖。

`sms_student_imports` 保存基本资料预览、逐行结果和恢复状态；未执行预览按 TTL 清理。原始文件、未映射字段和敏感列不持久化。沿用 `sms_batch_locks` 串行处理学生写入。审计只记录批次、操作者和字段名，不包含完整导入内容。

文件解析在有限内存和超时的工作线程中进行，XLSX 解压总量和单个内部文件均有限制。解析使用 [SheetJS 官方发行包](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/) 与 `csv-parse`。

接口：

- `POST /sms/api/student-import/parse`：`filename`、base64 `content`、可选 `sheet`，返回工作表、表头、资料行和建议列对应。
- `POST /sms/api/student-import/preview`：`filename`、`headers`、`rows`、`mapping`，可选 `allowNewRows`、`skipRows`。
- `GET /sms/api/student-import`：最近 100 条已开始批次。
- `GET /sms/api/student-import/:id`：批次明细。
- `POST /sms/api/student-import/:id`：确认或续办。
