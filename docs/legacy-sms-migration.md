# 旧 Python SMS 迁移预览

作者：FubukiHanasaki。版本保持 0.3.0。

## 只读预览

```bash
node scripts/preview-legacy-sms.cjs \
  --source /absolute/path/sms-backup.db \
  --target-config /absolute/path/hydro/config.json \
  --out /private/new-preview-directory
```

需要 Python 3（仅使用标准库 SQLite）和插件已安装的 MongoDB 驱动。`--python` 可指定 Python 可执行文件。源文件必须是通过 SQLite backup 接口生成的一致性备份，不直接读取线上正在写入的数据库文件。配置中的 `uri` / `url` 用于读取指定目标数据库；脚本不会打印连接串或认证资料。生产预览建议使用仅有读取权限的 MongoDB 账号和独立配置文件，无需修改线上 Hydro 配置。

该命令不加载旧站程序、不调用任何写接口、不创建 MongoDB 导入任务，也没有 apply/import 模式。SQLite 使用只读 URI、query_only 和读取事务；MongoDB 仅执行 find。输出目录拒绝覆盖，目录权限 0700、报告权限 0600，含学生基本资料，应保存在私有位置。本项目测试报告统一放在 `.tmp/`，不提交 Git。

输出：

- `preview.html`：可离线打开、筛选、查看候选依据及 Rating 明细的预览；不会连接网站。页面内更改映射只影响当前浏览器，下载映射文件后才保存。
- `preview.json`：完整预览，包括源文件 SHA-256、目标数据快照、逐人候选、基本资料、Rating 明细和问题。
- `review-decisions.json`：待确认映射，`confirmed` 和每行 `approved` 始终为 false。生成或下载该文件不代表授权导入。

## 匹配与范围

以旧学生关联账号的用户名、学生姓名与 Hydro 用户名/实名、旧学号与 Hydro 标识的精确匹配产生候选，只做 Unicode NFKC、首尾空白和大小写规范化。多个候选不按优先级擅自选择；不根据拼音、相似姓名、校区后缀猜测身份，不把旧学生 ID 或学号当作 Hydro UID。

唯一候选同时通过资料校验、账号保护和同名检查后才产生建议。旧档案同名、实名不一致、多档案指向同 UID、受保护账号、已绑定档案均须人工处理。只读预览中的建议也必须由操作者确认。未匹配默认暂缓，不创建账号、不重置密码、不改 Hydro 权限或班级身份。

仅迁移姓名、性别、年级、学校、学生状态、入学日期和学习阶段。旧状态为空按现有插件规则建议设为「在校」，须在确认范围时一并核对。生日、联系方式、家长资料、内部备注及已移除字段不纳入迁移。

Rating 使用 `elo_change.rating_after` 和 `elo_change.exam_date`。没有时区的日期时间按 Asia/Shanghai（UTC+08:00）解释，保留历史实际时间，不使用统一重算的 `created_at`。同一学生同一时间不同分数、无效值、未来时间及当前分数与末条历史不一致均列为问题；不自动更改时间或取最大值。旧模拟赛实体不导入，历史以绝对分数检查点迁移，不虚构真实计分比赛次数。

## 确认后的执行约束

此文描述后续执行的必要条件，不表示已经导入，也不提供绕过确认的写库命令。

1. 明确批准具体映射文件的内容和源文件哈希、目标库、资料及 Rating 范围；冲突、未匹配行继续暂缓，手动修正的 UID 必须重新校验。
2. 生产执行前备份目标数据库及插件相关集合，记录账号和既有档案/Rating 状态；先在克隆或隔离测试库演练，并核对恢复办法。源文件保持不变。
3. 确认选中 Hydro UID 存在、唯一、未被别的学生绑定、可由现有导入接口绑定；重新读取目标账号、档案和 Rating，目标变化时重新预览，不沿用旧确认。
4. 通过插件现有学生批量导入的预览/确认接口导入基本资料，所有选中行显式填写 Hydro UID，防止留空触发自动建号；保留批次 ID、每行结果及新档案 ID，不覆盖旧档案。
5. 学生成功绑定后，通过 Rating 导入接口分批（每批最多 500 条）预览并以最新 revision 确认。同 UID、同时间、同分数幂等去重，不同分数整批拒绝。失败停止后续批次，记录已完成部分，重试时重新预览。
6. 校验资料字段、绑定关系、每人历史条数及时间、末条分数、排行榜和个人曲线；确认原有账号密码、权限、子域成员及既有档案保持预期。部分完成不能标记为全部成功。

现有接口说明见 [学生导入](student-import.md) 和 [Rating](rating.md)。迁移期间的并发写入、失败续办和恢复需要在最终执行工具中显式处理，不使用直接 insert 覆盖业务集合的方式绕过鉴权与审计。
