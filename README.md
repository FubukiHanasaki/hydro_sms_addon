# Hydro SMS Addon

作者：**FubukiHanasaki** · AGPL-3.0-or-later · 当前版本：0.2.0

Hydro 原生学生信息管理插件。只使用 Hydro 账号登录，业务授权和学生资料保存在插件自己的 MongoDB 集合中，不运行 Python 服务，不依赖旧 SMS 数据库。

## 功能

- `/sms#rating` Rating 总榜、近 30 天进步榜、历史曲线与数据概览；接管原版 RP 和等级称号，支持比赛难度配置、自动结算与旧数据导入。计算核心独立，详见 [Rating 系统与导入接口](docs/rating.md)。
- `/sms` 学生档案面板：分页、姓名搜索、状态/年级/所在子域/学校组合筛选、新建和编辑。
- 学生基本资料、敏感联系资料、内部备注分开处理。
- 新建时 UID 留空自动创建姓名全拼账号，重名追加数字，初始密码与用户名一致；支持快捷搜索并绑定已有账号。
- 编辑时清空 UID 只解绑，不会创建账号；同一 UID 只能关联一份学生档案。
- 生日支持 `2012`、`2012-06`、`2012-06-15`，保留填写精度；也接受斜线分隔并规范化存储，生日始终按敏感资料授权。
- 基本资料包含姓名、性别、年级、学校、状态、入学日期和学习阶段；不再提供学号、校区、竞赛等级、目标阶段，也不单设出生年份。
- 在现有 Hydro 用户资料页中增加「学生资料」标签，后端按当前访问者过滤字段；Rating 合并到「个人简介」，采用分段色带折线图，资料页标签即时切换。
- 模块化权限：默认/自定义模板、按操作和班级的临时授权、生效与失效时间、独立撤销、实际权限查看；原有指定学生专项授权保留。详见 [权限与鉴权](docs/authorization.md)。
- 乐观锁避免并发覆盖；Hydro UID 唯一索引；敏感读取和写入审计。
- 复用 Hydro 默认主题的栅格、section、侧栏菜单、表格、表单和按钮；支持桌面、移动端及深色主题，资料弹窗内部滚动。

Rating 已接入旧系统计算规则，并提供按 Hydro UID、分数、记录时间导入历史序列的预览与确认流程；不要求迁移旧考试数据。学生基本资料现已支持 Excel/CSV 批量导入，先预览及识别重复，再创建普通 Hydro 账号并自动绑定；敏感资料不纳入文件导入，详见 [学生批量导入](docs/student-import.md)。

教师档案（`/sms#teachers`）支持绑定已有 Hydro 账号、管理基本资料和联系方式；管理员或有相应权限者管理档案，教师默认只查看本人档案，内部备注不向本人展示。现有任课教师尚未建档时显示「待建档」，不会自动生成档案。详见 [教师档案](docs/teachers.md)。

课程管理（`/sms#courses`）与排课管理（`/sms#schedules`）为独立入口：课程保存实际授课与考勤，排课保存每周计划。班级概览和 Rating 分析位于「班级与子域 → 详情」，详见 [课程、排课与班级详情](docs/teaching.md)。

批量升年级位于「学生档案」右上角，支持复学选择、预览、重复执行提醒和批次撤销；「账户管理」支持为未绑定学生批量补建账号、勾选账号批量重置密码。两个页面均可查看「批量记录」，详见 [批量操作](docs/bulk.md)。

各功能列表和详情提供 Excel/CSV 导出，包含筛选后的全部结果，导出受对应操作和数据范围限制；教师档案不提供导出。入口与隐私规则见 [按功能导出](docs/exports.md)。

排课管理顶部「批量排课」支持 Excel/CSV 导入或粘贴 CSV，先预览并检查班级、教师和教室冲突，确认后整批发布；未完成批次可续办或放弃。详见 [批量排课](docs/schedule-batch.md)。

教务管理（`/sms#academic`）提供课次状态跟进、待录课程与考勤待补筛选、每日统计和按实际日期计数的课程报表，支持直接处理课次及 Excel/CSV 导出，详见 [教务管理](docs/academic.md)。

## 安装

要求 Node.js 22+、Hydro 5.0.7+、MongoDB 7+ 和 `@hydrooj/ui-default`。已在 Hydro 5.0.7 / UI 4.58.5 / MongoDB 8.0.16 下验证。当前使用默认 UI 的模板扩展点，尚未适配 `ui-next`。

在插件目录运行：

```bash
npm ci
npm run check
```

让运行 Hydro 的环境可以读取插件目录，然后注册绝对路径：

```bash
hydrooj addon add /absolute/path/to/hydro_sms_addon
```

重启 Hydro。配置中应保留 `@hydrooj/ui-default`。插件不需要额外网络端口。

使用独立 Hydro profile 时，请在该 profile 中注册插件，并按部署方式重启 Hydro 网站进程。

## 初始化管理员

**没有默认管理员，也不会继承 Hydro 超级管理员或域管理员权限。** 未指定插件管理员时，不允许创建档案或授权。首次部署后应由服务器维护人员明确指定插件管理员。

从服务器明确指定已存在的 Hydro UID：

```bash
node scripts/admin.cjs grant 123 /absolute/path/to/hydro/config.json
node scripts/admin.cjs list 0 /absolute/path/to/hydro/config.json
node scripts/admin.cjs revoke 123 /absolute/path/to/hydro/config.json
```

配置文件需包含 `uri` 或 `url`，示例中的 123 应替换为本人确认的 UID。CLI 不打印数据库凭据，拒绝撤销最后一名插件管理员。管理员任命和撤销均留痕。CLI 的执行者拥有服务器权限，应由服务器维护人员操作。

当前版本按单个 Hydro 实例管理一套学生档案，权限跨 Hydro 域一致；不是按域隔离的多机构版本。当前宿主用户查询使用标准、无前缀的 `user` 集合，暂不支持 Hydro 的自定义 collectionMap/prefix 配置。

## 权限规则

| 权限 | 能力 |
| --- | --- |
| `students.read` | 查看授权范围内的基本资料 |
| `students.sensitive` | 查看敏感资料和内部备注；编辑敏感资料还需要 `students.write` |
| `students.write` | 编辑授权范围内的基本资料 |
| `students.bind` | 修改档案对应的 Hydro UID |

学生专项授权必须包含 `students.read`，每个 UID 保存一组学生权限。模块权限另支持模板和多条按操作、班级及时间的追加授权；新建、导入、审计和其他管理操作逐项鉴权。只有插件管理员可修改权限配置。默认「现有身份权限」保留此前行为，不自动扩大现有教师的学生档案权限；显式绑定「任课教师」模板或追加模块授权后才扩大对应能力。完整目录、依赖和范围规则见 [模块权限与鉴权](docs/authorization.md)。

绑定学生不需要追加授权即可查看自己的基本与联系资料，但不能因此编辑、绑定账号或查看内部备注。插件管理员若同时绑定自己的档案，也不能通过页面或接口读取本人内部备注。

账号绑定是一项高权限操作：绑定后会授予目标 UID 本人查看能力，请先核实账号归属。修改/解除绑定通过独立权限检查，不依据前端角色标签。

所有 API 从 Hydro 当前会话读取操作者，拒绝使用请求中的 UID 冒充操作者；页面不接收旧 SMS 会话。服务端不返回未授权字段，列表始终排除联系资料和内部备注，不把这些字段放入 `UiContext`。私有页面和接口使用 `Cache-Control: private, no-store`。

写请求使用同源 `Origin`、`X-SMS-Request: 1` 和 JSON Content-Type 校验；插件没有开放跨域接口。反向代理应按 Hydro 文档正确配置外部协议和 Host，否则同源写请求会被拒绝。

## 学生条件筛选

年级和学校选项取自当前操作者可读取的学生档案，按精确值匹配；姓名使用文字搜索。所在子域根据学生绑定的 Hydro UID 查询 `domain.user`，仅 `join: true` 且子域仍存在的关系参与筛选；未绑定账号的学生不会匹配具体子域。学生加入多个子域时可分别被检索，同一学生不重复计数。默认选择「全部子域」，不会按当前页面所在域自动缩小插件权限。

所有条件以 AND 组合，先校验数据范围，再统计总数和分页。筛选选项也应用相同的数据范围，防止通过下拉框获取未授权学生的年级、学校或子域信息。条件变化会回到第一页；重置会清除姓名和全部筛选。

## 班级与子域

面板统一入口为「班级与子域」，直达地址 `/sms#organization`。旧的 `#domains`、`#classes` 链接也会打开此面板。

- 一个班级对应一个 Hydro 子域。名称取自 `domain.name`，说明与子域公告共用 `domain.bulletin`，账号成员统一使用 `domain.user` 中 `join: true`、UID 大于零的关系。插件不再维护独立的学生账号名册副本。
- 既有子域（包括主站）直接显示为班级与子域，无需重复新建。`sms_classes.domainId` 有唯一索引，只补充班型、学年、上课安排、地点、开班/归档状态及插件教师身份。新建时一次创建 Hydro 子域和插件扩展资料；其所有者为当前账号。
- 管理员在成员列表中直接选择普通成员、任课教师或学生身份，并点击「保存身份」。此操作只修改插件身份，不会重新加入子域或改变 Hydro 域角色；显式保存的身份优先于根据学生档案推导的默认显示。
- 添加成员分为搜索、选中、点击「确认添加」三个步骤，点击候选项本身不会写入。主域以外的子域将账号设为学生时仍要求已绑定学生档案。移除成员同时退出子域并失去对应班级访问，保留原 Hydro 域角色，不允许移除所有者。Guest 等内置访客不列入名册和人数。
- 主域 `system` 的所有真实账号默认加入，不要求学生档案；可以直接设为任课教师或学生。插件启动时补全遗漏的主域成员关系，当前账号请求时也会自愈，新建账号使用 Hydro 原生默认加入流程。主域名册查看时再次补齐遗漏成员；主域不提供移除成员，停用账号应通过账户管理完成。普通主域成员只能读取自己的成员信息，教师身份和敏感资料权限仍由插件独立判断。
- 教师须同时具有插件分配的教师身份和实际域成员关系，才能查看完整基本名册；学生只能查看自己的成员条目。Hydro 域角色不自动授予插件教师、管理员或敏感资料权限。教师身份不扩大「学生档案」的独立授权范围。
- 名册只返回用户名、UID、姓名与插件成员身份。班级详情对授权教师返回基本学生资料，不返回联系方式、生日和内部备注。
- 名册搜索支持用户名、学生姓名及 UID，20 人一页；成员行统一列宽与操作位置，分页位于弹窗固定底栏，列表独立滚动。支持桌面、手机和低高度窗口。
- 资料和成员操作共享版本号与按域更新锁。旧版本请求返回 409，避免成员增减与资料编辑互相覆盖。域更新通过 Hydro 模型刷新宿主缓存；锁会在进程中断后两分钟失效。
- 涉及 Hydro 与插件的写入没有跨集合强事务。失败会保留 `syncState: failed` 与审计记录，重新读取时显示 Hydro 的实际名称和成员，可刷新版本后重试。新域创建失败时，同一 ID 可从新建窗口重试；不会因此重复创建班级。
- 部署前应核对旧版是否有多个班级关联同一域；如有，须先整理其业务资料，插件拒绝任意选择一条覆盖。旧版遗留的独立学生名册不再作为账号入班依据，应以域成员为准核对；不会自动删除旧字段。本工作区切换时没有旧班级记录。
- 不迁移在班日期、时段覆盖或时间纠错验证。上课安排只是选填说明，入班、退班立即生效。归档保留名册，不提供班级/域硬删除及域角色权限编辑；课程、排课、考勤和分析通过「详情」管理。

### 关闭原版子域管理

插件加载期间，原版域仪表盘、资料、成员、角色、权限、用户组、加入设置、自助加入及创建页的 GET/POST 请求均在原处理器执行前拒绝（403），包含 `/d/:domainId` 前缀。原版 `/home/domain` 的 GET 转到 `/sms#organization`，其所有写操作拒绝；通用 API 的 `domain.group` 写操作也拒绝。禁止操作对 Hydro 超级管理员同样生效。域首页、题目、作业、比赛、排名和域切换继续使用 Hydro。

原版管理导航在服务端隐藏，默认主题的固定入口改指插件，关闭 JavaScript 也不会显示旧入口。插件继续使用宿主模型完成已鉴权的操作，没有修改 Hydro 核心文件。移除插件并重启 Hydro 后，原版路由与默认主题入口恢复；运行时注销插件时恢复被替换的 UI checker。主题入口覆盖按默认 UI 4.58.5 编写，升级主题时应复核 `templates/partials/nav.html` 和 `templates/components/home.html`。

## 账户管理

侧栏「账户管理」或 `/sms#accounts` 提供按用户名、学生姓名、UID 和启用状态查找账号、分页、创建账号、修改用户名、重置密码、停用及重新启用。仅插件管理员可访问页面对应 API；普通用户和教师不能通过直接请求操作账号。列表不返回邮箱、密码散列、盐、登录 IP 或认证器资料。

- 创建使用 Hydro 用户名校验和 `PRIV_DEFAULT`，提供内部保留邮箱与窗口请求标识，重复提交不会创建多个账号。输入密码至少 6 个字符，保持 Hydro 的 255 字符上限。账号创建不自动创建学生档案或授予插件管理权限。
- 改名使用 `UserModel.setUname`，密码重置使用 `UserModel.setPassword`，启用状态使用 `UserModel.setPriv`，由宿主更新缓存。停用只移除用户资料/登录权限位，重新启用只恢复该位，保留其他权限和历史数据。
- 密码重置与停用同时调用 `TokenModel.delByUid`，撤销旧会话和该用户已有令牌。重置不移除双重验证；插件不记录或返回明文密码，不记录密码内容摘要，审计只记录操作及字段名称。
- 内置账号、插件管理员和带额外 Hydro 全局权限的账号在此页受保护，只读且不能重置密码、改名或停用。自身密码可继续使用 Hydro 的个人安全设置修改。此页不提供设置 Hydro 超管、修改全局权限、移除双重验证或硬删除账号的功能。
- 每个账号使用独立版本号和短期更新锁；冲突需刷新重试。宿主写入失败后，应关闭窗口刷新核对实际状态再重试，不自动重放密码操作。

## 数据与一致性

- `sms_students`：字符串主键、基本/敏感资料、内部备注、可选 Hydro UID、版本号与创建/更新操作者。
- `sms_account_jobs`：自动建号请求标识、操作者、资料摘要和处理状态；不保存密码或完整学生资料。
- `sms_authorization`：默认模板、绑定、临时授权及配置版本。
- `sms_schedule_batches`：批量排课预览、冲突检查和统一发布，准备阶段的计划不对读端展示，详见 [批量排课](docs/schedule-batch.md)。
- `sms_teaching_plans` / `sms_teaching_adjustments` / `sms_teaching_records`：每周排课与生效版本、临时调整、独立实际课程及考勤，详见 [教学管理](docs/teaching.md)。
- `sms_student_imports`：学生基本资料导入预览、逐行执行及账号绑定恢复，详见 [学生批量导入](docs/student-import.md)。
- `sms_bulk_jobs` / `sms_batch_locks`：批量操作预览、逐项执行结果及恢复锁，详见 [批量操作](docs/bulk.md)。
- `sms_teachers`：教师账号关联、基本资料、联系方式、内部备注及版本。
- `sms_classes`：唯一子域关联、班级扩展资料、教师 UID、显式成员身份、共享版本、同步状态与更新记录。
- `sms_account_state` / `sms_account_locks`：账户管理版本与短期操作锁，不保存密码。
- `sms_org_locks`：按域保存的短期更新锁，包含随机令牌和失效时间，不保存成员资料。
- `sms_policy`：单文档授权策略、管理员 UID、授权有效期与版本号。
- `sms_rating_head` / `sms_rating_sources` / `sms_rating_summaries` / `sms_rating_changes` / `sms_rating_contests`：Rating 当前批次、原始输入、用户投影、历史记录和比赛配置，详见独立文档。
- `sms_audit`：操作者、操作、对象、字段名称、时间和结果；不保存完整档案或敏感值。

资料和授权分别使用单文档原子更新与版本检查。自动建号通过持久化请求标识、唯一用户名和固定内部邮箱关联重试，因此本阶段不要求 MongoDB 副本集。以后涉及多实体强事务时，再引入副本集与事务。

写入先记录审计意图，再更新业务数据，最后标记结果。崩溃可能留下 `pending`（面板显示「待核对」），需要结合目标版本核对，不能据此自动重放写入。未实现跨集合强事务。授权在每次请求时重新读取，没有长期权限缓存。

自动建号仅限插件管理员。前端为每次新建窗口生成请求标识，失败后在同一窗口重试会复用标识；重复或并发提交不会创建多份账号。账号已经创建而档案尚未保存时，会留下可恢复的 `account_ready` 记录，重试继续绑定该账号；不会自动删除已经创建的 Hydro 账号。如果关闭窗口而未重试，服务器维护人员应核对未完成记录。此流程没有跨集合强事务保证。

自动账号通过 Hydro `UserModel.create` 写入，仅使用 `PRIV_DEFAULT`，不会继承管理员权限。用户名采用姓名全拼并规范化为小写，`ü` 使用 `v`，冲突追加数字；不足 3 个字符时补 `01`，过长时截取前 27 个字符以容纳后缀。系统生成保留内部邮箱，不要求填写真实邮箱；创建成功后向操作者显示用户名和初始密码，插件不保存明文密码。修改学生姓名不会自动重命名或重置账号密码。

账号快捷搜索只向插件管理员和具有对应学生绑定权限的人员开放，最多返回 10 条用户名、UID 和是否可绑定，不返回邮箱或学生敏感资料。

已移除字段的旧存储不会在升级时直接删除；列表、详情和用户资料页统一通过字段白名单过滤。编辑保存基本资料时写入新的字段结构。

资料编辑提交完整的基本资料分组；未获敏感权限的用户无法写入该分组。版本冲突返回 409，需重新打开档案后确认修改。学生基本资料支持文件批量导入；当前提供按权限过滤的资料导出；尚无档案硬删除或学生自助修改功能。
