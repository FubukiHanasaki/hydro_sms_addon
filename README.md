# Hydro SMS Addon

Hydro 原生学生与教务管理插件，复用 Hydro 账号和登录会话，在同一站点内提供学生档案、教师档案、班级与子域、课程、排课、考勤和 Rating 管理。

**版本：0.3.0** · **作者：FubukiHanasaki** · **许可证：AGPL-3.0-or-later**

仓库：[FubukiHanasaki/hydro_sms_addon](https://github.com/FubukiHanasaki/hydro_sms_addon)

## 功能一览

安装后通过顶部「学生管理」或 `/sms` 进入面板。菜单和操作按当前账号的插件权限显示。

| 模块 | 主要功能 | 入口 |
| --- | --- | --- |
| 学生档案 | 基本资料、敏感资料、账号绑定；按姓名、状态、年级、子域和学校筛选；文件导入、批量升年级 | `/sms#students` |
| 教师档案 | 绑定 Hydro 账号，维护教师基本资料、联系方式和内部备注 | `/sms#teachers` |
| 班级与子域 | 一个班级对应一个 Hydro 子域，共享名称、说明和成员；分配任课教师、管理成员身份、按 UID 批量导入成员、归档及查看详情 | `/sms#organization` |
| 课程管理 | 登记实际授课、管理考勤、关联排课课次、补充班外学生 | `/sms#courses` |
| 排课管理 | 按教师筛选的每周课表、08:00–22:00 时间轴、周期计划、调课、停课、补课与批量排课 | `/sms#schedules` |
| 教务管理 | 课次状态跟进、待录课程和考勤待补筛选、每日统计及实际课程报表 | `/sms#academic` |
| 模拟赛管理 | 关联 Hydro 比赛、参赛班级、难度、类型、来源、归档、列表导出、历史 Rated 初始化和管理员核验；详情进入原生比赛页 | `/sms#exams` |
| Rating | 总榜、进步榜、班级筛选、称号、历史曲线、比赛设置、管理员核验结算和记录导入 | `/sms#rating` |
| 账户管理 | 创建、查找、改名、重置密码、启停账号，以及学生账号批量补建和密码重置 | `/sms#accounts` |
| 访问授权 | 默认权限模板、自定义模板、按操作及班级授权、授权有效期和实际权限查看 | `/sms#permissions` |
| 操作记录 | 按权限查看和导出业务审计记录 | `/sms#audit` |

各功能在对应列表或详情中提供 Excel / CSV 导出，导出遵守读取权限和数据范围；教师档案不提供导出。

学生资料显示在 Hydro 用户资料页的「学生资料」标签中。Rating 曲线合并到「个人简介」，采用分段色带、折线和节点展示；排名页及用户称号使用插件 Rating，替换原版 RP 展示。Rating 计算与业务存储分为独立模块，便于调整算法。

### 数据和权限边界

- 只使用 Hydro 账号登录。插件管理员、模块权限和教师身份独立授权，**不会自动继承 Hydro 超级管理员、子域所有者或域管理员的身份**。
- 学生本人可查看已绑定档案的基本资料与敏感联系资料；其他人查看敏感资料需要明确授权。内部备注不向学生本人展示，包括同时拥有管理员身份的本人。
- 一个 Hydro UID 最多绑定一份学生档案。基本资料与敏感资料分开鉴权，普通列表不返回联系方式、生日或内部备注。
- 课程记录实际授课与考勤；排课记录计划，两者独立管理。导入排课不会自动生成实际课程或考勤。
- Rating 的公开身份展示按查看者的 SMS 档案绑定判断：绑定学生或教师档案后正常显示；未绑定（含未绑定的管理员及访客）在排名页、榜单接口和榜单导出中只显示按榜单顺序编号的「选手1、选手2」等匿名名称，不提供真实 UID、用户名、姓名、个人主页链接或他人历史入口，也不能按身份条件反查。未绑定账号查看他人主页时不展示 Rating、称号及记录，直接访问他人历史或导出历史也会被拒绝；查看本人 Rating 保持可用。档案绑定撤销后，后续请求立即按未绑定规则处理。
- 班级与子域共用 Hydro 成员关系，教师身份由插件单独分配。主域的真实账号默认加入；普通成员无需绑定学生或教师档案即可按其 Hydro 权限使用子域功能，并按插件模板读取所在班级的基础信息、课程和排课。学生档案、敏感资料及管理操作仍独立鉴权；其他子域将成员明确设为学生时仍需要绑定学生档案。
- 插件加载期间会隐藏并禁止原版子域管理入口和接口，由「班级与子域」统一管理；题库、比赛、作业、域首页和域切换仍使用 Hydro。「班级与子域」标题旁提供「班级列表 / 我的子域」选项卡；顶部子域菜单的「管理」直接进入「我的子域」。该选项卡复用原生个人子域列表与收藏接口，保留收藏、取消收藏、角色显示和进入子域，收藏后刷新页面即可在顶部快捷切换。个人收藏不会修改成员关系或权限。移除插件并重启后恢复原版管理入口。

## 安装与配置

### 运行要求

| 项目 | 要求 |
| --- | --- |
| Node.js | 22 或更高版本 |
| Hydro | 5.x，最低 5.0.7；包依赖范围为 `^5.0.7` |
| MongoDB | 7 或更高版本，使用 Hydro 对应的数据库 |
| 界面 | `@hydrooj/ui-default`；尚未适配 `ui-next` |
| 安装工具 | Git、npm，以及可用的 Hydro CLI |

当前插件按**单个 Hydro 实例共用一套业务数据**设计，不是按子域隔离的多机构系统。使用标准、无前缀的 Hydro 集合名称，暂不支持自定义 `collectionMap` / collection prefix。升级 Hydro 或默认主题时，应先核对模板扩展点的兼容性。

### 1. 下载并安装依赖

以运行 Hydro 的系统账号执行，选择该账号可读取的持久化目录：

```bash
git clone https://github.com/FubukiHanasaki/hydro_sms_addon.git
cd hydro_sms_addon
npm ci
npm run check
```

`npm run check` 执行 TypeScript 静态检查。插件由 Hydro 加载，无需单独编译前端，也不需要独立进程或额外端口。

### 2. 注册插件

在插件目录中执行：

```bash
hydrooj addon add "$PWD"
```

必须使用与网站进程相同的系统账号、Hydro 安装和 profile。注册后可查看插件列表：

```bash
hydrooj addon list
```

确认列表保留 `@hydrooj/ui-default`，并包含本插件的绝对路径。随后按现有部署方式重启 Hydro 网站进程，使路由、模板和静态资源生效。

### 3. 检查配置与入口

- 访问 `/sms`，使用已有 Hydro 账号登录。
- 插件直接复用 Hydro 的 MongoDB 连接；正常运行无需另填数据库连接或插件环境变量，首次加载会建立所需集合和索引。
- 首次安装没有默认插件管理员，须完成下节初始化后才能进行管理操作。
- 反向代理需向 Hydro 正确传递对外协议和 Host。插件写接口校验同源 `Origin`，代理配置不一致可能导致保存请求被拒绝。
- 所有示例路径与 UID 都应替换为实际部署值。数据库配置和导出文件应保存在私有位置。

## 初始化插件管理员

先准备一个已存在且可登录的 Hydro 账号，在其用户资料页确认 UID。服务器维护人员从插件目录执行：

```bash
node scripts/admin.cjs grant 123 /absolute/path/to/hydro/config.json
```

`123` 为示例 UID；配置文件必须指向**运行站点使用的数据库**，包含 `uri` 或 `url`，可选 `name` 指定数据库名称。脚本直接连接 MongoDB，需要对应读写权限，不要求事先拥有插件页面权限。

查看管理员清单：

```bash
node scripts/admin.cjs list 0 /absolute/path/to/hydro/config.json
```

撤销某名插件管理员：

```bash
node scripts/admin.cjs revoke 123 /absolute/path/to/hydro/config.json
```

脚本不会打印数据库凭据，任命和撤销会记录审计，并拒绝撤销最后一名插件管理员。页面权限模板不能任命插件管理员。

初始化后，用该账号重新打开 `/sms`。在「访问授权」中按用户名、学生姓名、教师姓名或 UID 查找其他账号，配置默认模板和必要的追加授权；通过「我的权限」或「查看实际权限」核对生效操作和数据范围。

内置模板包括现有身份权限、教务、任课教师、只读教务、学生本人和无业务默认权限。任课教师模板按实际任教班级生效，敏感资料、账户管理和 Rating 管理等能力仍需对应授权。完整规则见 [模块权限与鉴权](docs/authorization.md)。

## 数据导入

建议顺序为：初始化管理员 → 导入学生并绑定账号 → 配置班级成员与任课教师 → 维护教师档案 → 导入排课 → 按需导入 Rating。学生文件也可同时携带最后一次 Rating，无需重复导入。

### 班级成员批量导入

入口：「班级与子域 → 成员 → 批量导入」，需要该班级的 `classes.members` 权限。

上传 XLSX 或 CSV，第一行填写表头 `UID`（也支持 `Hydro UID`、`OJ UID`、`用户 UID` 等明确的修饰性表头），其后每行一个已有 Hydro 账号的正整数 UID。XLSX 读取首张工作表；每次最多 200 人，文件不超过 2 MB。

```csv
UID
62
222
223
```

预览展示账号、绑定学生姓名、导入身份和逐行检查结果。已绑定学生档案的新增成员默认设为学生，未绑定的设为普通成员；已有成员跳过并保留原身份及 Hydro 域角色，不创建账号或档案。重复 UID、无效账号、公式单元格等错误需要修正后重新上传。

表头识别会统一全角字符、大小写和常见分隔符。学生资料和批量排课也支持明确的修饰性表头，例如 `学生姓名（必填）`、`就读学校名称`、`当前年级`。不采用任意包含匹配；`UUID`、`旧UID`、`家长姓名` 等不会误认。多个候选列或字段含义冲突时不自动选列，需手动指定列对应；成员导入需修正为唯一的 UID 列。

点击「确认导入」才写入成员关系，每次写入独立鉴权并记录操作日志。预览只对上传者和目标班级有效，一小时后过期；名册或档案绑定变化需要重新预览。重复确认不会重复添加。导入中断时可能部分完成，刷新名册核对后重新上传即可跳过已加入者；不会自动回滚已完成的成员关系。

### 学生基本资料：Excel / CSV

入口：「学生档案」右上角 →「批量导入」。

1. 下载页面中的 CSV 模板，使用 Excel 或其他表格工具填写。支持 `.xlsx`、`.xls` 和 CSV；第一行是表头，每次最多 **1000 行、50 列、2 MB**。
2. 按下表填写资料。绑定已有账号时先核对 Hydro UID，明确选择每行的账号处理方式。
3. 上传并点击「读取文件」，有多个工作表时选择目标工作表，再检查列对应。
4. 点击「预览导入」，核对新增、绑定、重复、疑似重复、错误和跳过状态；检查用户名、UID、Rating 与结算时间。疑似重复默认不选中，错误行不能选中。
5. 确认选中行后点击「确认导入」。预览只读，确认后才创建档案、账号或写入 Rating。
6. 查看逐行结果；完成后可导出结果及本批账号。发生中断时，从「批量导入 → 导入记录 → 详情」继续同一批次。

| 字段 | 填写方式 |
| --- | --- |
| 姓名 | 必填 |
| 性别 | 男、女、未填写或空 |
| 年级、学校、学习阶段 | 选填文本 |
| 学生状态 | 在校、休学、离校；空时为在校 |
| 入学日期 | 选填，Excel 日期或 `YYYY-MM-DD` / `YYYY/M/D` |
| Hydro UID | 绑定已有账号时填写；创建新账号时留空 |
| 账号处理 | `绑定已有账号`、`创建新账号` 或 `跳过` |
| Rating | 可选分数，范围 0–100000，0 是有效值 |
| Rating结算时间 | 与 Rating 同时填写或同时留空；支持北京时间或带时区的日期时间 |

**账号处理规则：**

- `绑定已有账号`：必须提供 UID，不修改已有账号的用户名、密码或 Hydro 权限。
- `创建新账号`：UID 必须留空，自动生成姓名全拼用户名，较短拼音补数字至 6 位，冲突追加数字，初始密码与用户名一致，账号仅有 Hydro 普通默认权限。交付后应让使用者修改密码。
- `跳过`：该行不会创建账号、档案或 Rating。Excel 中隐藏或筛选掉某行并不能使其跳过。
- 如果文件没有「账号处理」列，UID 留空会按自动建号处理。建议始终使用带该列的模板，避免误建账号。

敏感资料、生日、联系方式、家长信息、地址、内部备注和班级身份不通过此文件导入。公式单元格须先转为值。重复数据不会直接覆盖已有档案；受保护账号不能通过学生导入绑定。

仅需导入最后结算分数时，每位学生填写一组 `Rating` 和 `Rating结算时间` 即可。空值不等于 0 分，Excel 日期时间保留时分秒，无时区时间按北京时间解释。含 Rating 的批次还需 `rating.import` 权限；基本资料导入需要全局学生导入、新增、读取、修改和绑定权限，插件管理员默认具备。

导入按行处理，可能部分完成。若资料已完成而 Rating 未完成，批次会保留待处理状态，续办会核对账号绑定并去重，不重新创建账号。详细限制、重复识别和恢复流程见 [学生批量导入](docs/student-import.md)。

### Rating 历史：CSV / JSON

入口：「Rating → 导入记录」。用于向**已绑定学生档案的 Hydro UID**追加绝对分数检查点；每批 **1–500 条**，支持上传文件或粘贴内容。

```csv
uid,rating,recordedAt
123,1680,2026-01-10T18:00:00+08:00
124,1950.25,2026-01-11T18:00:00+08:00
```

以上是格式示例，UID、分数和时间均应替换为实际值。

1. 准备 `uid`、`rating`、`recordedAt` 三列，或包含这些字段的 JSON 记录。
2. 上传或粘贴后生成预览，核对 UID、记录时间、新增及重复数量。
3. 确认后导入，再检查排行榜及用户资料页曲线。

同 UID、同时间、同分数会去重；同时间不同分数阻止导入。无效日期、未来时间、负分、无账号或未绑定学生的 UID 会被拒绝。确认时数据版本发生变化，需要重新预览。检查点不计作真实比赛次数，仅导入一个检查点时曲线不会凭空生成更早的历史。

实际计分比赛在「模拟赛管理」关联 Hydro 比赛、选择参赛班级并设置难度与 Rated。首次进入时，插件管理员需预览过往比赛并明确选择哪些保留 Rated；未选择的不自动标记，导入分数检查点保留。比赛结束、正式提交全部评测完成后，由插件管理员打开「核验」，检查官方成绩并确认后更新 Rating；启用 Rated 或定时任务不会自动发布未核验成绩。修改配置、正式成绩重测后需要重新核验。已发布快照在再次核验前保留。计算规则、JSON 格式和接口见 [Rating 文档](docs/rating.md)，模拟赛、权限与代码包流程见 [模拟赛管理](docs/exams.md)。

### 批量排课：Excel / CSV

入口：「排课管理 → 批量排课」，支持文件上传或粘贴 CSV，每批 **1–100 条计划、2 MB**。

1. 先在「班级与子域」确认目标班级及成员，并将授课账号设为任课教师。
2. 下载模板，填写班级/子域 ID、排课名称、教师 UID、起止日期、星期和开始/结束时间，可附教室、状态、颜色及备注。
3. 读取文件并确认列对应，生成预览。
4. 处理班级、教师和非空同名教室的时间冲突。存在错误或冲突时不能确认。
5. 确认后统一创建每周计划；有中断时在批次记录中继续或放弃未发布批次。

预览和确认都会检查冲突及权限；计划完整准备后才整批发布到课表。该操作不生成实际课程或考勤。字段和规则见 [批量排课](docs/schedule-batch.md)。

## 日常使用与维护

### 建议配置顺序

1. 在「访问授权」按人员职责分配模板和数据范围。
2. 在「班级与子域」维护资料、成员和任课教师身份；Hydro 子域所有者不会自动成为插件任课教师。
3. 在「教师档案」绑定教师账号并补充资料。
4. 在「排课管理」建立计划，通过「课程管理」登记实际授课与考勤。
5. 在「班级与子域 → 详情」查看概览、实际课程、排课、考勤和 Rating 分析；在「教务管理」跟进未完成事项。

### 更新与备份

更新前备份 Hydro 数据库和部署配置，备份应包含 Hydro 账号/子域数据及插件的 `sms_*` 集合；只备份插件目录不能恢复业务资料。

在插件目录中执行：

```bash
git pull --ff-only
npm ci
npm run check
```

随后重启 Hydro 网站进程，检查 `/sms`、管理员权限及关键业务页面。插件采用版本校验、操作锁和批次恢复记录；部分业务不具备跨集合强事务保证，失败后应查看原批次或实际记录再重试，不直接修改数据库来绕过校验。

学生和课程导出文件可能包含个人资料，本批新建账号导出还可能包含初始密码，请按访问权限保存和交付，不上传公开仓库。数据库连接配置、备份和会话凭据也不应随插件源码发布。

### 常见问题

| 情况 | 检查项 |
| --- | --- |
| 看不到管理按钮或菜单 | 确认插件管理员已初始化，或对应操作和数据范围已授权；重新打开页面查看实际权限 |
| 子域所有者看不到预期教学信息 | 检查实际成员关系、插件任课教师身份及默认权限模板；Hydro 域角色不代替插件授权 |
| 保存返回 403 | 检查会话、插件权限，以及反向代理传递的外部协议和 Host |
| 修改或确认返回 409 | 资料、权限或预览版本发生变化，刷新记录或重新预览后再确认 |
| 导入中断或显示部分完成 | 从导入/批次记录打开原批次继续，先核对逐行结果 |
| Rating 尚未更新 | 在模拟赛管理完成历史 Rated 初始化；比赛结束并评测完成后，由插件管理员核验并发布 Rating |
